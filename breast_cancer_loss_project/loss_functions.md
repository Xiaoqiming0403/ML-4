# 乳腺癌数据集上的自定义损失函数实验

## 1. 实验目的

本实验的目标是：在乳腺癌二分类数据集上，固定模型结构为 Logistic Regression，只改变损失函数，观察不同损失函数对训练效果和测试效果的影响。

直觉上，我们可能会认为：

```text
只要预测错了，损失函数变大，就可以训练模型。
```

这个想法有一定道理，但并不完整。一个好的损失函数不仅要在预测错误时给出较大惩罚，还需要满足更多条件，例如：

- 梯度方向要合理
- 错得越离谱时，梯度最好还能推动模型修正
- 优化过程要稳定
- 最好具有凸性或较好的优化性质
- 输出概率最好有合理的概率解释
- 在小数据集和大数据集上都应该比较可靠

因此，本实验尝试构造多种损失函数，包括线性型、平方型、多项式型、指数型和 margin 型损失，并与标准 Logistic loss 进行对比。

## 2. 数据集与模型

实验使用 UCI Wisconsin Diagnostic Breast Cancer 数据集。数据集包含 569 个样本，每个样本有 30 个数值特征，标签为：

```text
M：恶性
B：良性
```

本实验将恶性 `M` 记为正类 `1`，良性 `B` 记为负类 `0`。

模型固定为 Logistic Regression：

```text
z = w^T x + b
p = sigmoid(z) = 1 / (1 + exp(-z))
```

所有实验都使用同一个模型结构，只替换损失函数。

数据划分方式为：

```text
train / validation / test = 70% / 15% / 15%
```

另外，为了观察小数据集上的表现，还额外构造了一个小训练集版本，只使用约 80 个训练样本，其余验证集和测试集保持不变。

## 3. 为什么不能只看“预测错损失大”

“预测错了损失大”只是损失函数的一个基本要求，但不是充分条件。

举例来说，如果某个损失函数在预测错时损失很大，但它的梯度非常小，那么模型仍然很难修正错误。

对于梯度下降来说，真正推动参数更新的是梯度，而不仅仅是损失值本身：

```text
w <- w - lr * gradient
```

如果损失大但梯度接近 0，模型就可能“知道自己错了”，但没有足够力量改正错误。

这也是很多自定义损失函数的问题：它们看起来合理，但梯度性质不好。

## 4. 标准 Logistic Loss

标准 Logistic Regression 使用二元交叉熵，也叫 Logistic loss：

```text
L = -[y log(p) + (1 - y) log(1 - p)]
```

其中：

```text
p = sigmoid(z)
```

它的梯度非常简洁：

```text
dL/dz = p - y
```

这个性质非常重要。对于正类样本，如果模型非常自信地预测错了，例如 `y=1` 但 `p≈0`，那么：

```text
p - y ≈ -1
```

梯度不会消失，模型仍然会被强力推动去修正错误。

这就是 Logistic loss 好用的一个关键原因。

## 5. 本实验尝试的损失函数

### 5.1 Logistic BCE

公式：

```text
L = -[y log(p) + (1-y) log(1-p)]
```

特点：

- 标准逻辑回归损失
- 概率解释清楚
- 梯度简单
- 对自信但错误的预测惩罚强
- 优化性质好

### 5.2 Linear Probability Loss

公式：

```text
L = y(1-p) + (1-y)p
```

解释：

- 如果真实标签是 1，损失是 `1-p`
- 如果真实标签是 0，损失是 `p`

它确实满足“预测越错，损失越大”。但是它的问题是梯度中包含：

```text
p(1-p)
```

当模型非常自信但预测错误时，`p` 接近 0 或 1，`p(1-p)` 会接近 0，梯度反而变小。

也就是说，它在“最需要修正”的地方可能更新不够有力。

### 5.3 Squared Probability Loss

公式：

```text
L = 0.5(p-y)^2
```

这是类似均方误差的损失。它也能用于二分类，但通常不是 Logistic Regression 的首选。

它的问题和线性概率损失类似：由于 `p = sigmoid(z)`，梯度中也会出现 `p(1-p)`。当模型进入饱和区时，梯度会变小。

### 5.4 Quartic Probability Loss

公式：

```text
L = 0.25(p-y)^4
```

这是一个更高阶的多项式损失。它会让较大的概率误差受到更强惩罚。

但它也有明显问题：

- 对较小误差的梯度可能更小
- 仍然受 sigmoid 饱和影响
- 优化过程不如 Logistic loss 稳定

### 5.5 Exponential Margin Loss

先定义：

```text
y' = 2y - 1
margin = y' z
```

指数型 margin 损失为：

```text
L = exp(-margin)
```

如果样本被正确分类且 margin 很大，损失会很小。如果样本被错误分类，margin 为负，损失会快速变大。

它的优点是对错误样本惩罚很强。缺点是可能出现梯度爆炸，因此实验中对 margin 做了裁剪。

### 5.6 Squared Hinge Margin Loss

公式：

```text
L = max(0, 1 - margin)^2
```

这个损失来自支持向量机思想。它不直接关注概率，而是关注分类边界的 margin。

如果样本不仅被分对，而且 margin 足够大，损失就是 0。如果 margin 不够，则产生惩罚。

它适合分类，但概率解释不如 Logistic loss 清楚。

### 5.7 Cubic Hinge Margin Loss

公式：

```text
L = max(0, 1 - margin)^3
```

这是 squared hinge 的更高阶版本。它对 margin 不足的样本惩罚更强。

但高阶损失可能让梯度更不稳定，因此学习率需要更小。

### 5.8 Log-cosh Margin Loss

公式：

```text
L = log(cosh(1 - margin))
```

它是一个比较平滑的 margin 型损失。相比 hinge，它更光滑；相比 exponential，它不会增长得过于夸张。

这个损失函数是一个折中尝试，目的是让损失在错误时变大，同时保持梯度相对平滑。

## 7. 为什么 Logistic Loss 仍然更好

虽然实验中有些自定义损失函数取得了很高分，但 Logistic loss 仍然是更标准、更可靠的选择。

### 7.1 梯度性质更好

Logistic loss 的梯度是：

```text
dL/dz = p - y
```

当预测非常错误时，梯度仍然很大，模型能有效修正错误。

而线性概率损失、平方概率损失、多项式概率损失的梯度都包含：

```text
p(1-p)
```

当模型非常自信时，`p(1-p)` 接近 0。如果此时模型预测错了，梯度反而可能很小。

这说明它们虽然“错了损失大”，但不一定“错了更新也大”。

### 7.2 概率解释更合理

Logistic loss 是负对数似然，对应伯努利分布假设。最小化 Logistic loss 等价于最大化数据出现的概率。

这意味着它不仅能做分类，还能输出比较合理的概率。

一些自定义损失函数可能也能分对类别，但输出概率不一定可靠。例如，模型可能能判断哪个类别更可能，但概率值本身不一定有统计意义。

### 7.3 优化性质更成熟

对于线性模型，Logistic loss 具有良好的凸优化性质。虽然实际实现中还会受到数值、正则化、学习率等因素影响，但总体来说它比很多随意构造的损失更稳定。

指数型损失虽然也能工作，但可能出现梯度过大；多项式型损失可能出现梯度过小或优化变慢；hinge 型损失虽然适合分类，但概率解释不如 Logistic loss。

### 7.4 泛化更可靠

在小数据集上，一个自定义损失函数可能碰巧表现很好。但这不代表它在更复杂、更大、更噪声更多的数据集上也表现好。

Logistic loss 是经过大量理论和实践验证的损失函数，因此在不同数据集上的可靠性更高。

## 8. 小数据集可行，大数据集是否可行？

本实验说明，在乳腺癌这种小而干净的数据集上，自定义损失函数确实可能可行。

原因包括：

- 数据集样本少
- 特征质量高
- 类别区分较明显
- 噪声相对较少
- 线性模型已经能取得较好效果

但是，这不能直接推广到大数据集。

在大数据集上，自定义损失函数可能遇到更多问题：

1. **噪声更多**  
   自定义损失可能对异常点过于敏感，例如 exponential loss。

2. **类别分布更复杂**  
   如果类别不平衡，简单损失函数可能严重偏向多数类。

3. **优化更困难**  
   梯度过大或过小的问题会在大数据集训练中更明显。

4. **概率校准更重要**  
   大数据集常用于真实决策场景，概率是否可靠很重要。Logistic loss 在这方面更有优势。

5. **泛化风险更高**  
   一个损失函数在小数据集上表现好，可能只是因为数据简单或划分偶然。

因此，结论应该是：

```text
小数据集上，自定义损失函数可以尝试，而且可能取得不错效果；
但大数据集上，不能只凭“预测错了损失大”来设计损失函数，
还必须考虑梯度、稳定性、概率解释和泛化能力。
```

## 9. 对实验结果的理解

本实验中 Linear probability loss 在全量训练集上取得了 100% 测试准确率。这是一个有趣现象，但不能简单得出“线性损失比 Logistic loss 更好”的结论。

原因有三点：

第一，测试集较小，只有约 15% 的样本。一次划分中的满分可能有偶然性。

第二，乳腺癌数据集本身相对容易，不同损失函数都能找到较好的分类边界。

第三，线性概率损失的梯度性质并不理想，尤其是在模型自信但错误时，梯度可能变小。

因此，更稳妥的结论是：

```text
在这个小数据集上，自定义损失函数可以工作；
但 Logistic loss 仍然是理论更完善、泛化更可靠的标准选择。
```

## 10. 最终结论

本实验验证了一个重要观点：损失函数不是只要“预测错了损失大”就足够。

一个好的损失函数还需要：

- 有合理的梯度
- 易于优化
- 对错误样本有足够修正能力
- 输出概率有解释意义
- 在不同数据规模和噪声条件下稳定

Logistic loss 的优势在于，它同时满足这些要求。它来自概率建模，梯度形式简单，优化性质较好，并且能输出有意义的概率。

自定义损失函数可以作为探索实验，尤其适合帮助理解损失函数和梯度之间的关系。但如果是实际项目或更大规模数据，Logistic loss 仍然是更可靠的默认选择。
