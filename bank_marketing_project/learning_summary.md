# 此次任务学习总结

## 1. 数据集选择

本次任务最开始使用的是已有项目中的数据和代码，但为了让实验报告更加完整，我们重新选择了 UCI Bank Marketing 数据集。这个数据集的任务是预测客户是否会订阅银行定期存款，属于典型的二分类问题，正好适合使用 Logistic Regression。

通过这个过程可以学到，数据集选择不仅要看“能不能训练”，还要看它是否适合实验目标。对于本次作业来说，合适的数据集应该满足几个条件：第一，它应该是分类任务；第二，标签要明确；第三，数据量不能太小，否则很难体现不同优化方法的时间和效果差异；第四，特征要有一定复杂度，方便进行预处理、分析和报告撰写。

Bank Marketing 数据集共有 41188 条样本，包含数值特征和类别特征，目标变量 `y` 表示客户是否订阅定期存款。相比只有几百条样本的小数据集，它更适合比较 full-batch gradient descent、mini-batch gradient descent 和 SGD 的训练时间与分类效果。

## 2. Logistic Regression 的基本原理

本次任务的核心模型是 Logistic Regression。虽然名字里有 Regression，但在这里它用于分类任务。对于二分类问题，模型先对输入特征做线性打分：

```text
z = w^T x + b
```

然后通过 sigmoid 函数把线性得分映射成概率：

```text
p = 1 / (1 + exp(-z))
```

这里的 `p` 表示样本属于正类的概率。在本任务中，正类是客户订阅定期存款，也就是 `y = yes`。

模型训练的目标是让预测概率尽量接近真实标签。我们使用二元交叉熵作为损失函数：

```text
L = -[y log(p) + (1 - y) log(1 - p)]
```

再通过梯度下降不断更新参数 `w` 和 `b`。本项目中没有直接调用 sklearn 的 LogisticRegression，而是使用 numpy 手写 sigmoid、loss、gradient 和参数更新过程，这样能更清楚地理解模型从数学公式到代码实现的完整过程。

## 3. 数据预处理

Bank Marketing 数据集中既有数值特征，也有类别特征。逻辑回归本质上需要数值输入，所以类别特征必须先转换成数值形式。本项目使用 one-hot encoding 对类别特征进行编码。

例如，`job`、`marital`、`education`、`contact`、`month` 等字段本身是字符串类型，不能直接参与矩阵运算。one-hot 编码会把一个类别字段拆成多个 0/1 特征。这样模型就可以学习不同类别对最终预测结果的影响。

对于数值特征，本项目使用标准化处理：

```text
x_scaled = (x - mean) / std
```

需要注意的是，标准化时只能使用训练集的均值和标准差，然后把同样的变换应用到验证集和测试集。这样可以避免数据泄露。如果使用全部数据计算均值和标准差，就相当于提前看到了验证集和测试集的信息，会让实验结果不够严谨。

此外，代码中还将偏置项 `b` 合并进了参数向量。具体做法是在特征矩阵最后添加一列全为 1 的特征，这样模型参数的最后一项就相当于偏置项。

## 4. 三种梯度下降方法

本次任务实现并比较了三种梯度下降方法：full-batch gradient descent、mini-batch gradient descent 和 stochastic gradient descent。

Full-batch gradient descent 每次使用整个训练集计算一次梯度，然后更新一次参数。它的优点是梯度方向稳定，loss 变化比较平滑；缺点是每个 epoch 中更新次数少，如果数据量很大，每次更新的计算成本也比较高。

Mini-batch gradient descent 每次使用一小批样本计算梯度。本项目中使用的 batch size 是 256。它是深度学习和机器学习中最常用的训练方式，因为它在稳定性和效率之间取得了比较好的平衡。实验结果也显示，mini-batch 方法整体表现较好。

SGD 每次只使用一个样本计算梯度并更新参数。它的更新非常频繁，但梯度噪声也更大，训练过程可能更不稳定。在本任务中，SGD 的训练时间明显更长，因为它的参数更新次数远多于 mini-batch 和 full-batch。

通过这三种方法的对比可以学到，优化方法不仅影响模型效果，也影响训练时间。实际项目中通常不会单纯选择理论上最精确的方法，而是选择综合效率和效果都较好的方法。

## 5. 学习率与学习率调度器

学习率决定了每次参数更新的步长。如果学习率太小，模型收敛会很慢；如果学习率太大，loss 可能震荡甚至无法收敛。因此学习率是模型训练中非常重要的超参数。

本项目比较了多个学习率，例如 0.02、0.05、0.1 和 0.2。不同学习率下，模型的 loss、F1 和 AUC 会有细微差别。

在此基础上，我们又加入了类似 `ReduceLROnPlateau` 的学习率调度思想。它的逻辑是：如果验证集 loss 连续若干轮没有明显下降，就把学习率乘以一个较小的 factor，例如 0.1。

这样做的好处是，训练前期可以用较大的学习率快速接近较优区域；当模型进入平台期后，再降低学习率，让参数更新更加细致。相比固定学习率，scheduler 可以让训练过程更加灵活。

本项目中还进一步改进了 scheduler：它不再只观察训练 loss，而是观察验证集 loss。这样更符合机器学习实验规范，因为验证集更能反映模型的泛化能力。

## 6. 正则化与 Weight Decay

正则化的作用是限制模型参数过大，从而减少过拟合风险。本项目中使用的是 L2 正则化，也可以理解为 weight decay。

加入 L2 后，损失函数会多一项：

```text
lambda / 2m * ||w||^2
```

对应到梯度中，会多出一项：

```text
lambda / m * w
```

这样模型在训练时不仅要降低分类损失，还要尽量保持参数不要过大。

本项目参考了 PyTorch 中 `weight_decay=0.0001` 的设置，在 numpy 代码中实现了等价的 L2 正则。实验表明，weight decay 对结果有一定影响，但单独依靠它并不能解决类别不平衡问题。它更适合作为一种稳定训练和减少过拟合的辅助方法。

## 7. 类别不平衡问题

Bank Marketing 数据集中，正类 `yes` 的比例只有约 11.3%，负类 `no` 占绝大多数。这是一个典型的类别不平衡问题。

如果只看 accuracy，模型很容易看起来表现不错。因为即使模型大量预测 `no`，也能获得较高准确率。但这样的模型对真正重要的正类客户识别能力可能很差。

因此，本项目没有只关注 accuracy，而是重点关注 precision、recall 和 F1。特别是 recall，它表示真实正类中有多少被模型成功识别出来。

为了解决类别不平衡问题，本项目加入了 class weight。具体做法是给正类更大的权重：

```text
pos_weight = negative_samples / positive_samples
```

在当前训练集中，这个值约为 7.876。也就是说，模型在计算损失和梯度时，会更重视正类样本。实验结果显示，加入 class weight 后，recall 和 F1 有明显提升。

## 8. 阈值调优

逻辑回归输出的是概率，不是直接输出类别。通常默认使用 0.5 作为分类阈值：

```text
p >= 0.5 -> yes
p < 0.5 -> no
```

但在类别不平衡任务中，0.5 不一定是最优阈值。由于正类样本较少，很多真实正类的预测概率可能低于 0.5，如果仍然使用默认阈值，就会导致 recall 较低。

因此，本项目在验证集上搜索最佳阈值。具体做法是在 0.05 到 0.95 之间尝试多个 threshold，并选择验证集 F1 最高的阈值。

实验结果说明，阈值调优带来了明显提升。原始 mini-batch 模型在 0.5 阈值下 F1 约为 0.51；加入阈值搜索后，F1 提升到 0.61 以上。进一步结合 class weight 和 scheduler 后，F1 提升到约 0.63。

这说明模型本身的概率排序能力不错，但默认阈值没有充分利用这种能力。

## 9. 评价指标

本项目使用了多个评价指标，而不是只看 accuracy。

Accuracy 表示整体预测正确的比例。在类别平衡的数据集中，它通常比较直观。但在类别不平衡场景下，accuracy 可能具有误导性。

Precision 表示模型预测为正类的样本中，有多少是真正的正类。它关注的是预测正类的准确性。

Recall 表示真实正类样本中，有多少被模型成功找出来。它关注的是正类的覆盖率。

F1 是 precision 和 recall 的调和平均，更适合在类别不平衡任务中综合评价模型。

AUC 衡量模型对正负样本的排序能力。即使在某个固定阈值下 F1 不高，只要 AUC 较高，就说明模型仍然有较好的区分能力，可以通过调整阈值进一步改善分类结果。

本项目最终最佳模型的特点是：accuracy 略低于原始模型，但 recall 和 F1 明显更高。这说明模型更重视识别正类客户，更适合当前业务目标。

## 10. Duration 特征分析

Bank Marketing 数据集中有一个重要特征 `duration`，表示通话持续时间。实验发现，使用 `duration` 时模型效果明显更好；去掉 `duration` 后，F1 和 AUC 都明显下降。

这说明 `duration` 对预测结果有很强的信息量。一般来说，通话时间越长，客户订阅定期存款的可能性可能越高。

但是，这个特征也存在一个需要在报告中说明的问题：在真实营销预测场景中，通话持续时间通常是在通话结束后才知道的。如果我们的目标是在通话前预测哪些客户更可能订阅，那么 `duration` 就可能造成数据泄露。

因此，报告中可以同时展示 with duration 和 without duration 的结果。with duration 代表在已有完整通话信息后的预测能力，without duration 更接近真实的提前预测场景。

## 11. 实验结果的主要结论

原始 mini-batch logistic regression 在默认 0.5 阈值下，accuracy 较高，但 recall 和 F1 不够理想。这是因为数据集中正类比例较低，模型更倾向于预测负类。

加入阈值搜索后，模型能更好地平衡 precision 和 recall，F1 明显提升。

加入 class weight 后，模型更重视少数类 `yes`，recall 进一步提升。虽然 accuracy 有所下降，但这是合理的，因为模型不再单纯追求预测多数类，而是更积极地识别正类客户。

最终最佳模型是 mini-batch logistic regression 加上 class weight 和 validation scheduler，并使用验证集搜索得到的最佳阈值。它在 F1 和 recall 上明显优于原始模型，更适合当前类别不平衡的二分类任务。

## 12. 后续可以改进的方向

第一，可以进一步细化阈值搜索。当前阈值搜索步长是 0.01，已经比较细，但仍可以结合 precision-recall 曲线进行更系统的分析。

第二，可以尝试不同的 class weight，而不只使用负样本数除以正样本数。比如可以把 class weight 当成超参数，在验证集上搜索。

第三，可以加入更多正则化实验，例如比较不同 L2 系数对参数大小、loss 和 F1 的影响。

第四，可以做错误分析，查看哪些客户被错分，分析错分样本在年龄、职业、联系方式、上次营销结果等特征上的分布。

第五，可以和 sklearn 的 LogisticRegression 进行对比。虽然作业核心要求是 numpy 手写实现，但 sklearn 可以作为参考基线，用来验证自己实现的合理性。

第六，如果不受模型限制，可以尝试非线性模型，例如决策树、随机森林或梯度提升树。这类模型通常更适合表格数据，但它们不属于本次“从零实现 Logistic Regression”的核心要求。
